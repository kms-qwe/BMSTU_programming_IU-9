# Лабораторная №2 — Метод сопряжённых градиентов (MPI, Python)

Этот проект содержит параллельную реализацию метода сопряжённых градиентов (CG) для решения СЛАУ `Ax=b` с использованием `mpi4py`. Поддерживаются два варианта из задания:

- **Вариант 1 (`--variant dup`)** — векторы `x` и `b` дублируются в каждом процессе.
- **Вариант 2 (`--variant dist`)** — векторы `x` и `b` разрезаются между MPI‑процессами аналогично строкам матрицы `A` (требуется больше коммуникаций).

Матрица по умолчанию берётся **модельная** из методички: диагональ `2.0`, прочие элементы `1.0` (т.е. `A = J + I`). Для неё произведение `A v` вычисляется *не сохраняя матрицу* (матрица‑свободно): `A v = (sum(v)) * 1 + v`. Это позволяет брать очень большие `N` (и добиться ≥30 секунд на 1 ядре при подходящих `N, ε`). Для валидации также есть опция `--matrix dense`, где локальный блочный фрагмент матрицы хранится явно (только для малых `N`).

## Запуск решателя

Пример (решение модельной задачи с известным ответом: `x* ≡ 1`):

```bash
mpiexec -n 4 python cg_mpi.py --N 20000000 --eps 1e-8 --variant dup --matrix model --problem ones
```

Параметры:
- `--N` — размерность.
- `--eps` — критерий останова: `||r||₂ / ||b||₂ < eps`.
- `--variant {dup,dist}` — дублирование или разрезание `x,b`.
- `--matrix {model,dense}` — модельная (без хранения) или плотная (только для малых `N`).
- `--problem {ones,sine}` — правая часть: 
  - `ones`: `b = (N+1)*1`, истинное решение `x* = 1`.
  - `sine`: `u_i = sin(2π i / N)`, `b = A u`, истинное решение `x* = u`.

На `rank 0` печатается краткая сводка, первые 5 компонент решения, а также JSON‑блок с результатами (для парсинга скриптами).

## Валидация на малых размерах

Сравнить `--matrix model` и `--matrix dense` (малые `N`):

```bash
mpiexec -n 2 python cg_mpi.py --N 2000 --eps 1e-10 --variant dist --matrix dense --problem sine
mpiexec -n 2 python cg_mpi.py --N 2000 --eps 1e-10 --variant dist --matrix model --problem sine
```

## Бенчмаркинг, ускорение и эффективность

Скрипт `bench_cg.py` сам запускает решатель на наборах процессов, усредняет время и строит три графика: `time_vs_cores`, `speedup_vs_cores`, `efficiency_vs_cores`.

Пример:

```bash
python bench_cg.py --solver ./cg_mpi.py --N 40000000 --eps 1e-8 --procs 1 2 4 8 16 --repeats 3 --variant both --problem ones --matrix model --mpi mpiexec --outdir bench_out
```

После выполнения в `bench_out/` появятся:
- CSV с «сырыми» результатами
- PNG‑графики:
  - время от числа ядер
  - ускорение `S(p) = T(1) / T(p)`
  - эффективность `E(p) = S(p) / p`

> **Совет по выбору N:** чтобы на 1 ядре было ≥30 секунд, увеличивайте `N` и/или ужесточайте `--eps`. Для модельной матрицы сложность одной итерации `O(N)`; CG обычно сходится за `O(√κ)` итераций (κ — число обусловленности).

## Замечания по корректности и воспроизводимости

- Разбиение по строкам *контигуозное* и независимо от числа процессов: при любом `-n` одинаковые глобальные индексы попадают в те же позиции своих локальных блоков, поэтому исходные данные генерируются детерминированно.
- Вариант `dup` действительно хранит полные `x,b` на каждом процессе и синхронизирует `x` через `Allgatherv` на каждой итерации.
- Вариант `dist` хранит только локальные куски `x,b`. Для модельной матрицы матвектор не требует `Allgather` (только `Allreduce` суммы), что демонстрирует преимущества знания структуры `A`. Для `--matrix dense` (валидация) используется `Allgatherv` в каждом матвекторе.
